# mem-manager · Step 2 共享内存池分配器 — 设计评审

> 背景：OS 共享内存最小粒度 **2MB**；业务大量申请 **小块** → 每块占满 2MB。
> 实测（已用 OS 全量 shm 日志交叉验证）：**真实需求 ~1.3GB，OS 实际占用 ~28.8GB，浪费 ~95%**。
> 目标：**池化小块**，把占用从 ~28.8GB 压向 ~1.3GB（约 20×）。

---

# 第 1 页 · 整体架构

```
          业务（不改代码，仍调 Platform_ShmMap / _ShmMapOnPg / _ShmUnmap）
                                  │
                            ┌─────┴─────  路由决策
                            │
           ┌────────────────┴─────────────────┐
        透传 OS                              进池（小块 + VA-same）
   (大块 / VA-differs / 关池)        ┌──────────┼───────────────┐
                                  名字表       引用计数        可插拔策略
                              name→(块,偏移)   原子增减     slab / freelist / bump
                                                            └ 池块 = OS ShmMap 的大块
   元数据（名字表 / 池块表 / 锁 / 配置）放「元数据共享内存」：CP 建、各进程 attach
   配置文件驱动池的大小 / 策略 / 节点
```

- **接口不变**：业务零改动；内部"小块走池、大块透传"。
- **数据读写零开销**：返回**裸指针**，业务直接读写；池子只在 `map/unmap` 介入，且属 **init-once**（启动期，稀少）。
- **可一键回滚**：`enable=false` → 全透传，等价 Step 1。
- **C 实现**（DP 无 C++/libc 也能用），复用 Step 1 的采集与工具验证效果。

# 第 2 页 · 路由：ShmMap 决策（含 NUMA）

```
Platform_ShmMap(flags, name, size):
  enable=false / size ≥ 阈值(2MB) / flags 非 VA-same(4/5)   ─→  透传 OS
  否则（小块 + VA-same）：
      无锁查名字表
        命中  ─→ attach：原子 refcount++，返回引用数        ← 高频、无锁
        未命中 ─→ 创建：选池 → 切块 → 登记 → refcount=1
                  （拿不到锁 / 池满 → 兜底透传）
```

**NUMA（部署固定：numa1 为主、numa0 少量）→ 按节点分池**
- **OnPg** 请求 → 用 `pgname` 解析的节点；
- **非 OnPg** 请求 → 用**调用方所在节点**（绑核固定，配置里写死 `pg→节点`）；
- ⇒ 每个核分配的小块落在**本地节点**池块上，不破坏局部性。

**并发**
- **attach（命中）**：全程**无锁**（acquire 查表 + 原子 refcount）。
- **创建（未命中）**：`TrySpinLock` + 兜底透传 → **永不死锁**，临界区只几行赋值。

# 第 3 页 · 可插拔分配策略：slab / freelist / bump

> **框架（路由 / 名字表 / 引用计数 / 锁 / NUMA / 地址反查）与策略无关；只有 `carve`/`release` 不同。**

| 策略 | 切分方式 | 内部碎片 | 外部碎片 | 速度 | 复用槽 | 最适合 |
|---|---|---|---|---|---|---|
| **slab** | 块切**固定大小槽** | 有（档间取整） | 无 | O(1) | ✅ | 运行期会复用槽 |
| **freelist** | 按**精确大小**切 + 合并 | 无 | **有** | O(n) | ✅ | 任意大小 + 频繁复用 |
| **bump** | **指针推进**、整块收尾回收 | 无 | 无 | O(1)（可无锁） | ❌ | **init-once / 长生命周期** |

- **选型建议**：纯 init-once → **bump**（精确、最快、最省）；会复用槽 → **slab**；通用大小+复用 → **freelist**。
- **配置选用**：可**全局选一种**，也可**按 size 范围分池混用**（小块 slab、长生命周期 bump）。
- 三者共用同一套并发模型与"名字共享 + 引用计数"语义。

# 第 4 页 · 配置项设计 + 评审注意事项

**配置项（INI 风格、十六进制字节、可演进、不改代码重编）**
```ini
[pool] enable=true  threshold=0x200000  poolable_flags=4,5
[pool.small]  strategy=slab  classes=0x4000,0x10000,0x40000  block_size=0x200000
[pool.long]   strategy=bump  range=0x40000:0x200000          block_size=0x800000
[numa]  pg1=1  pg0=0          ; 固定部署：pg/vcpu → 节点
```
- **加载**：CP 启动读配置 → 写入「元数据共享内存」→ **DP attach 不读文件**（DP 无文件 I/O）。

**评审注意事项（重点讨论）**
1. **不死锁但会降级**：`TrySpinLock` 拿不到 → 该次**透传**（省不了但系统照跑）；**不依赖锁崩溃健壮**。需监控"长期降级"。
2. **崩溃 / 引用数泄漏**：持锁进程崩 → 半截创建最多**泄漏一个槽**；进程崩未 unmap → refcount 泄漏。init-once 下影响小；**孤儿块回收策略待定**。
3. **同块多区域的隔离**：一个 2MB 池块装多个区域，attach 会映射**整块** → 可见同块其他数据（**前提：同平台、互信**）。这是一切池化的固有性质。
4. **VA 限定**：只池化 **VA-same(4/5)**；**flags 4 与 5 分池**（共享范围不同，隔离不能破）；VA-differs/process-shared **透传**。
5. **大块透传 + 段数量**：≥2MB 透传（浪费小）；**待确认：OS 对 shm 段数量是否有上限/每段固定开销** → 若有，再评估把部分大块也纳入池。
6. **定长上限 + 兜底**：元数据用定长数组（块表/名字表上限、`MM_NAME_MAX`）；超出 → **兜底透传**，不崩。
7. **地址反查**：`unmap` 只给地址 → 块区间查 + `offset→entry` 索引定位注册项；落不到池 → 透传 OS。
8. **验证与回滚**：复用 Step 1 的 `analyze_profile` / `crosscheck_os_log` 验证占用从 28.8GB 下降；`enable=false` 一键回滚灰度。

# 附 · 待评审拍板项
1. OS 对 shm **段数量**有无上限 / 每段固定开销？（影响是否纳入大块、阈值大小）
2. 默认**策略**与**大小类/块大小**初值（建议：纯 init-once 用 bump；否则 slab 16/32/64/128/256K，块 2MB）。

4. **孤儿块 / refcount 泄漏**的恢复要求（v1 是否接受弱一致、靠重启）。
